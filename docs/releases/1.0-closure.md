## 1. 版本定位

1.0 是**内部可试用 / 可演示版本**，不是全面开放商业化版本。

当前重点：

- 验证「原创 / 上传大纲改编 → 正文生成和导出」完整链路；
- 后台治理能力只作为管理员能力开放；
- Provider benchmark、real_call 等后台实验能力不入前台产品态。

## 5. 真实调用 / 扣费边界

**核心原则**：1.0 封版后，以下行为必须由用户手动触发，Codex / 自动化不得触发：

| 边界 | 说明 |
|------|------|
| 终端验证不触发真实 LLM | Codex 冒烟 / 验证只做 HTTP 状态码检查 |
| 用户浏览器点击「AI应用」| 触发故事梗概生成，走真实 LLM + 灵气扣费 |
| 用户浏览器点击「生成正文」| 触发正文单集生成，走真实 LLM + 灵气扣费 |
| 用户浏览器点击「批量生成 5 集」| 逐集触发，按单集规则逐集扣费 |
| 失败集是否扣费 | 以服务端真实调用和灵气流水为准 |
| 1.0 不新增独立扣费项 | 「批量生成」复用人物的单集扣费规则 |
| AI应用扣费 | 复用故事梗概生成规则 |
| 灵气账单审计 | 后台灵气规则仍需单独做一次账单审计（1.1 任务） |

**禁止环境变量**（Codex 不得设置）：

```bash
ALIYUN_IMS_ENABLE_REAL_CALL=true
LLM_REAL_CALL_ENABLED=true
SUBMIT_ALIYUN_IMS_ASR_ONCE
SUBMIT_LAPIAN_SCRIPTIZATION_LLM_ONCE
```

## 6. 已知非阻塞问题

### 6.1 Turbopack / ChunkLoadError 旧 chunk 残留

- **现象**：PM2 日志出现旧 chunk 加载失败告警
- **影响**：每次 `npm run build` 后旧 chunk 引用失效导致 PM2 自动 restart，重启后正常
- **当前状态**：HTTP 冒烟 0 个 500，PM2 online，暂记非阻塞
- **处理**：如浏览器白屏 / 500 再单独处理

### 6.2 extractJsonBlock warning

- **现象**：模型返回非标准 JSON 时出现 warning
- **影响**：当前不阻塞生成流程
- **处理**：后续可做模型输出解析稳健性优化（1.1）

### 6.3 整体导出版式可优化

- **现象**：Word 可正常导出，但人物重名、分集集纲重复展示
- **影响**：不影响导出功能
- **处理**：属 1.1 版式优化

### 6.4 人物生成重名

- **现象**：可能出现角色重名
- **处理**：需后续加唯一性校验（1.1）

### 6.5 批量生成质量受模型影响

- **现象**：可能遇到 `AI_JSON_TRUNCATED` / 质量校验失败
- **当前**：已能分类型提示（commit f280337），不阻塞主机制
- **处理**：1.1 加单集重试按钮

## 7. 高风险区禁止项

1.0 封版后，未经用户明确确认，不得执行：

| 禁止操作 | 说明 |
|----------|------|
| `prisma migrate deploy` / `prisma db push` / `prisma migrate reset` | 不执行数据库 migration |
| 删除 `dev.db` 或任何数据库文件 | 不删除数据库 |
| 修改 `.env` / `.env.local` | 不改环境变量 |
| 在终端触发真实 LLM 生成 | 不触发 `/api/original/generate-stream` 等 |
| 在终端触发 ASR / IMS 真实调用 | 不触发相关真实链路 |
| 设置 `ALIYUN_IMS_ENABLE_REAL_CALL=true` | 禁止 |
| 设置 `LLM_REAL_CALL_ENABLED=true` | 禁止 |
| 把后台实验能力混入前台产品态 | Provider benchmark / raw JSON / dry-run 等不入前台 |
| 修改 `types.ts` / Prisma schema / API routes / prompt | 封版后不扩大范围 |
